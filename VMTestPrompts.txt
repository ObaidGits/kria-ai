KEY FOR EXPECTED OUTCOMES
  [OK]        Command executed successfully on remote target
  [APPROVAL]  High-risk action may require explicit approval based on policy profile
  [PIN]       PIN gate expected when policy requires PIN for destructive/sensitive action
  [MULTI]     Multi-step flow (for example install + verify)
  [WARN]      Advisory warning (for example sudo non-interactive hint)
  [BLOCK]     Should be blocked by safety policy
  [FAILFAST]  Clear error with reason; no fake success

REMOTE ROUTING BEST PRACTICES
  1. For guaranteed remote routing, include one of these markers:
     - "on my VM"
     - "via SSH"
     - an explicit ssh pattern: ssh user@host "command"
  2. Most reliable format:
     Please run on my VM via SSH: ssh user@host "your command"
  3. If multiple remote targets are enrolled, include explicit host/user@host.
  4. Remote commands are non-interactive. If sudo asks password interactively,
     KRIA returns a sudo hint and command fails safely.

KNOWN REMOTE CAPABILITIES
  - Executes shell commands on enrolled targets through execute_fleet_command.
  - Auto target selection when target is omitted (best ready target).
  - Target hint supported through host/user@host/display/target id.
  - Remote package install/uninstall intent supported when prompt includes remote context.
  - Fleet events available through /api/fleet/events (SSE) for terminal/status telemetry.
