# Memory Graph Production Redesign — Risk, Control, and Rollback Register

**Status:** Planned/Unverified. Controls are design obligations, not evidence of implementation or acceptance.
**Scope:** MGR-001–MGR-048, MGD-001–MGD-046, single-user/single-process/single-laptop current release, F0–F6 backend-first order.

## 1. Method and Non-Negotiable Rollback Law

Likelihood and impact are Low/Medium/High/Critical. A trigger is an observable threshold that opens or escalates the risk. “Rollback” means a safe capability reduction, read-only mode, pre-production data reset, last verified derived generation, or removal of optional code. **Security/privacy/integrity fixes are forward-only:** never roll back to permissive authentication, remote exposure, direct/dual writes, client-only filtering, policy-weak cache reuse, plaintext-erasure claims, stale schemas, or dormant failed 3D. A committed authority transaction is never undone by restoring an older derived index; correction uses governed compensating records.

Critical residual risk is never silently accepted. Unknown evidence is not Low risk. Any open Critical or High truth, privacy, security, lifecycle, accessibility, or authority-integrity risk blocks F5. Risk closure requires a linked validation manifest and owner sign-off; a task checkbox is not closure.

## 3. Trigger and Escalation Rules

- Any protected marker, unauthorized count/topology difference, direct write path, partial authority commit, event mutation, false `Used`, false erasure, or corruption write is an immediate Critical failure: stop the gate and contain the capability.
- Retrieval/profile, renderer, migration, rebuild, or supply-chain uncertainty is not accepted by averaging. The affected capability remains Partial/Unavailable and the predecessor gate status remains unchanged.
- Performance breaches first remove decoration, optional analytics, background cognition, detached windows, and optional renderers. They never remove policy checks, provenance/truth, lifecycle controls, semantic list, correction, or evidence assertions.
- Recovery exits only after complete verification, not after a successful open or partial query. Derived rebuild never edits authority.
- Pre-production data reset is an allowed migration contingency, but it is not a substitute for deterministic schema, import, deletion, or corruption tests.

## 4. Residual-Risk Review Record

Each gate risk review artifact at `evidence/<gate>/<run-id>/reviews/risk.json` records risk ID, pre/post L/I, triggering evidence, control test manifest/hash, remaining exposure, owner, expiry, and verdict. `Accepted` is forbidden for Critical residual risk and cannot be used for unresolved High truth/privacy/security/lifecycle/accessibility/integrity risk at F5. Disabled optional capabilities may carry documented Medium residual risk only when the fallback satisfies all governing MGR criteria.
